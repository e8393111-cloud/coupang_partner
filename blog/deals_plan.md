# 하루특가 트랙 — 별도 운영 설계

> 결정 2026-08-04 (사용자): **새 블로그스팟** · **오늘 페이지 계속 갱신 + 주간 아카이브**

---

## 왜 분리하나

리뷰 블로그「어디사」는 이번 세션에 **후기 1,101건 기반 · 단점 선공개 · 반자동 함정 경고**로
차별점을 만들었다. 자동 발행되는 특가 목록을 같은 사이트에 섞으면 구글이 사이트 전체를
한 덩어리로 평가하므로, 애써 만든 신뢰가 같이 깎인다.

특가는 성격 자체가 다르다:

| | 리뷰 블로그「어디사」 | 특가 블로그 |
|---|---|---|
| 가치 | 판단·검증 (사람이 넣음) | 신선도·속도 (기계가 이김) |
| 수명 | 길다 (검색 유입) | 하루 (`endAt` 지나면 0) |
| 유입 | 검색 | 소셜·재방문·북마크 |
| 자동화 | 발행 직전까지만 | 전 구간 |

---

## 형태 — 한 페이지 갱신 + 주간 선별

**매일 새 글은 만들지 않는다.** 특가는 `endAt` 이 지나면 값이 0이 되는데,
날짜별 글을 쌓으면 **죽은 글이 매일 하나씩 늘어난다.** 그게 정확히 구글이
말하는 scaled content abuse 의 모양이고, 신생 블로그엔 치명적이다.

```
「오늘의 특가」 페이지 1개     하루 3~4회 갱신. 만료된 건 사라짐
                              → 항상 유효. 북마크·재방문 가치
「이번 주 베스트」 주 1회 글    그 주에 가장 쌌던 5개만 선별해 아카이브
                              → 새 글 신호 + 축적. 죽은 링크가 아니라
                                "이 정도 가격이면 싸다"는 기준선이 남는다
```

주간 글이 아카이브로서 값을 갖는 이유: 특가 가격은 **그 상품의 하한선 정보**다.
"지난주 이 제품이 9,900원까지 갔다"는 건 이번 주에 사려는 사람에게 유효한 판단 근거다.

---

## 만료 처리 (설계의 핵심)

하루특가 API 는 다른 목록 API 와 캐싱 규칙이 다르다.

- 각 상품에 `endAt` (ISO 8601, KST) 이 있다
- **`endAt` 지난 상품은 서버 응답에서 자동 제외**된다
- 문서 경고: *"캐시 만료를 `endAt` 보다 길게 잡으면 종료된 특가가 계속 노출되어,
  이용자가 링크를 눌렀을 때 특가가 아닌 가격을 보게 된다"*
- **편성이 없는 날은 `items` 가 빈 배열**로 온다 → 0건도 정상 동작해야 한다

→ 우리 규칙:
1. 갱신할 때마다 **API 를 새로 부른다.** 저장분을 재사용하지 않는다
2. 페이지에 각 상품의 **남은 시간**을 표기한다
3. 0건이면 "오늘은 편성이 없습니다" 로 정직하게 표시한다 (지난 것 재탕 금지)
4. 페이지에 **마지막 갱신 시각**을 크게 박는다 — 신선도가 이 페이지의 유일한 자산이다

---

## 갱신 주기

| 시각 (KST) | 이유 |
|---|---|
| 09:00 | 출근·오전 편성 반영 |
| 13:00 | 점심 시간대 |
| 19:00 | 퇴근 후 피크 |
| 23:00 | `endAt` 임박분 정리 (대부분 23:59 종료) |

호출 한도는 파트너 단위 10rps 라 4회/일은 여유가 넘친다.
쉐어링크는 **발급 후 저장해 재사용**한다 (같은 상품이 다시 편성돼도 재발급 불필요).

## 주소 — 확정

```
이름   오늘만
주소   oneulmandeal.blogspot.com     (2026-08-04 확정)
```

### 발행된 페이지 주소 (2026-08-05)

```
소개              /p/blog-page.html
개인정보처리방침   /p/blog-page_04.html
연락처            /p/blog-page_857.html
```

**교훈: 블로거 페이지 주소는 「첫 발행 시점의 제목」으로 만들어지고, 발행 후엔 못 고친다.**
제목이 한글이면 슬러그로 변환이 안 돼 `blog-page`, `blog-page_04` 로 떨어진다.
영어 제목으로 **먼저 발행**한 뒤 제목을 한글로 바꿔야 하는데, 발행 전에 바꾸면 소용이 없다.

→ 「오늘의 특가」 페이지는 이 순서를 반드시 지킨다:
`today` 로 발행 → 주소가 `/p/today.html` 인지 확인 → 그 다음 제목을 한글로 변경.
그 페이지는 북마크·재방문이 자산이라 주소가 실제로 중요하다.

(자동 갱신은 페이지 ID 로 하므로 슬러그가 지저분해도 자동화는 안 깨진다.)

어디사(`eodisanow`)와 같은 패턴(한글 로마자 + 영어 단어)이라 두 블로그를 한 세트로 소개하기 좋다.

**교훈: `curl` 404 는 가용성의 증거가 아니다.** 블로거가 예약해둔 이름이면
404 여도 개설 화면에서 거부된다. `todayonly` 가 그랬다.
짧고 일반적인 영어 단어일수록 예약돼 있다. 확인은 개설 화면에서만 된다.

## 안 하기로 한 것

- **날짜별 특가 글 양산** — 죽은 글이 쌓인다
- **리뷰 블로그에 섞기** — 사이트 전체 평가가 같이 깎인다
- **만료된 특가 재노출** — 문서가 명시적으로 경고하는 사항
- **`productUrl` 사용** — 수익 0원
